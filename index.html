Kura

An offline encrypted media vault for Android. Photos, videos, and GIFs are encrypted with AES-256-GCM on import, keyed from the Android Keystore, and never leave the device.

Sideload-only. Not on Play Store or F-Droid. Verify the signature before you install — see Install.

What it protects against

Encryption at rest only helps against specific situations. These are the ones it addresses.

Someone with the unlocked phone

Imported media is ciphertext on disk. The system gallery, the media scanner, and file browsers see an opaque blob, not images. App files also sit in a credential-encrypted sandbox at mode 0600.

A lost or stolen device

The AES key lives in the Android Keystore, which is bound to the device's secure hardware where the device has it. Pulling files off a flash dump yields ciphertext. Deleted files are overwritten with a single pass of zeros before unlinking, which is defence in depth rather than a promise: flash wears blocks out and remaps them, so this cannot guarantee erasure the way it would on a spinning disk.

Someone going through your gallery

A scrambled keypad layout, optional FLAG_SECURE, and a configurable auto-lock cover the shoulder-surfing and app-switcher cases. Three wrong PIN entries trigger a 24-hour lockout, and each attempt is timestamped into an intruder log you can review later.

Being asked to unlock it

A second, independent PIN opens a separate decoy vault. It is a real working vault with its own media, not an error screen. Database handles and decrypted buffers for the real vault are dropped on every lock, and unlocking the decoy does not clear the real vault's brute-force counter.

What it does not protect against

Every project in this space should tell you this part. It is longer than the marketing usually is.

  • A compromised device. Malware with root or a kernel exploit can read memory while the vault is open. Kura is not hardened against kernel-level attackers, and no app-level encryption can be.
  • Screen recording and external cameras. FLAG_SECURE blocks screenshots and previews, but it is optional and off by default, and it does nothing about a second phone pointed at the screen.
  • A four-digit PIN that you reuse. The PIN is stretched with PBKDF2-HMAC-SHA256 at 120,000 iterations, which raises the cost of guessing but does not make a weak PIN strong. The 24-hour lockout slows online attempts, not a patient attacker with the encrypted file. Treat the PIN as the weakest link, and prefer a longer one.
  • Coercion by someone who knows your habits. The decoy vault only helps if you use it consistently and it contains something plausible. If you never set one up, or set it up and then never post to it, it is not a defence.
  • Backups you exported carelessly. A .kura archive is encrypted with a passphrase you supply. That passphrase is the only thing protecting it, and Kura cannot recover it for you. There is no reset email and no backdoor, by design. The archive key derivation is PBKDF2 at 100,000 iterations — enough to stop casual attacks, below the usual guidance for dedicated offline cracking.
  • Bugs. This is version 1.0.0, written by one person and not independently audited. The cryptography is standard library primitives used conventionally, but the code around them has not been reviewed by anyone but its author. Do not treat it as reviewed.

How it is built

Plain Kotlin against the platform APIs, with almost no dependencies. All of these are checkable in the source.

Language
Kotlin, 20 source files, about 10,700 lines
UI
Android Views and Material Components. No Compose, no XML layouts beyond the framework's own.
Storage
Raw SQLiteOpenHelper, three tables. No Room, no ORM.
Dependencies
Six at runtime: appcompat, material, recyclerview, biometric, security-crypto, documentfile. All first-party AndroidX. No analytics, no crash reporting, no ad SDK, no network library.
Media crypto
AES-256-GCM per file. Master key from androidx.security.crypto.MasterKey in the Android Keystore, under the alias kura_master, using TEE or StrongBox where the device offers it.
PIN storage
PBKDF2-HMAC-SHA256, 120,000 iterations, 16-byte random salt, constant-time comparison. PINs set by older builds used a bare SHA-256 digest; those are re-derived with the KDF on next unlock.
Backup crypto
AES-256-GCM with a key from PBKDF2-HMAC-SHA256 at 100,000 iterations over a 16-byte salt. Each export gets a fresh salt and IV.
Shrinking
R8 code shrinking and resource shrinking are on for release builds.
Permissions
USE_BIOMETRIC only, inherited from security-crypto. The manifest declares no INTERNET, so the app cannot open a socket even if it wanted to.

Tagging

Most encrypted vaults are write-only: you can hide things, then never find them again. Kura tags media with booru-style category prefixes, so the vault stays searchable.

Four categories

c: character, a: artist, s: series, m: anything else. Each renders in its own colour. The prefix is stored but not shown in the tag chip, so the interface stays uncluttered while sorting and filtering still know what a tag means.

Search that forgives prefixes

Typing miku matches c:miku. Prefix a term with - to exclude it, and multiple terms are ANDed. There is autocomplete over the tags you have actually used, so the vocabulary is whatever your own library contains.

Separate media flows

Photos, videos, and GIFs each get their own view and can be hidden independently. Grid density, sort order, and favourites are configurable, and video autoplay and start-muted are per-setting rather than global.

Everything else

Import and export

Import from the system picker, share into the app from any gallery, or move whole folders in and out. Backups are .kura archives carrying a tag manifest, written wherever the system file picker points. Restore also reads the older .kuro and .vbooru formats and plain ZIP.

Import hygiene

Optional delete-original-after-import, hash-based duplicate skipping, and a maintenance action that clears out zero-byte records left behind by an interrupted delete.

Flip-to-panic

When the feature is on, turning the screen face down locks the vault immediately. Triggered by the accelerometer, not by a timer, so it does not fire while the phone is lying flat on a desk.

Look

Dark, AMOLED, and light themes, accent colours, a monochrome mode, and a choice of launcher icons. The tag guide and a coachmark tour are built in, and both are replayable from Settings.

Install

There is no store listing, so you install the APK yourself. Check the signature.

  1. Download kura_v1.0.1.apk and SHA256SUMS.txt from the v1.0.1 release page.
  2. Check the file you got. This catches a truncated or substituted download: 
    sha256sum -c SHA256SUMS.txt
  3. Then check who signed it. The key is stable for the life of the app, so this only needs doing once: 
    apksigner verify --print-certs kura_v1.0.1.apk

    Expect SHA-256: ad9059713b4d8d998c025f231023f18875699c7ef34b767bba6e5e6f114a1f3f. Android pins this certificate at first install, so it cannot change without becoming a different app rather than an update. A build that prints something else is not from this project.

  4. Allow your browser or file manager to install unknown apps, open the APK, then turn that permission back off.

The checksum covers the file as published, not a rebuild of it. Gradle does not produce bit-identical APKs across machines, so an APK you build from source will not match the hash — only the signing certificate will.

Questions

Does it need an account?

No. There is no signup, no server, and no recovery address. That also means nobody can reset your PIN for you, including the author.

Can I get my files back if I lose the phone?

Only from a .kura archive you exported first, and only with the passphrase you protected it with. There is no cloud copy and no backup service.

Is this an audited vault?

No. It uses standard primitives in the conventional way, but nobody outside the project has read the code. If you need an audited vault, this is not one.

Why no Play Store listing?

Sideloading sidesteps Play's data-safety form, which for an app like this is mostly a list of things it does not do anyway. The trade-off is that you have to check the signature yourself, which the install section covers.

Does the decoy vault look different?

No, deliberately. It is the same app, same icon, same layout. A decoy that gives itself away is worse than none, so the only difference is which PIN you entered and therefore which vault you land in.

Why is it called Kura?

蔵, the kanji for storehouse or vault. It is also close enough to how people already say "kura" that nobody has to learn a new word for it.

Support

Kura is free, has no ads, no tracking, and no accounts, and stays that way. If it earned its place on your phone, a tip helps keep updates coming. The same link is in the app under Settings.
